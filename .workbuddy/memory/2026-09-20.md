### 关键设计决策

- **隔离实现**：`do_orm_execute` + `with_loader_criteria` 双层过滤（租户 + 数据范围），
  业务代码零感知。
- **四件套同模块**：`Base`/Mixin/钩子必须都在 `core/db/`，否则 `core → models → core` 循环导入。
- **repository 是唯一数据入口**：`require_tenant_context()` 在入口 raise，把
  「漏设上下文 → 静默全量泄露」变成「启动即报错」。
- **跨租户走显式 bypass**（`bypass_context`），不用「忘了设上下文」。
- **不用 PostgreSQL RLS**：与连接池复用交互微妙，且漏设上下文会从「查到全量」
  变成「查到零行」，更难排查。应用层钩子错误暴露更直接。

## 踩到的坑（值得写进博客）

### 1. 「未设上下文 = 不过滤」必须显式定义

第一版把数据范围默认成 `SELF`，导致空上下文时注入 `owner_id = NULL` → 恒假 →
**查不到任何数据**。前 4 条验收标准全绿（看起来隔离完美），只有第 5 条反向验证
返回 0 条而不是 2 条才暴露。

修法：空上下文（tenant_id/user_id/dept_id 全 None）⇒ 不注入任何条件；
「不许静默全量」的防线挪到 repository 入口。

**教训：反向验证不是锦上添花，它是唯一能区分「过滤正确」和「过滤过头」的断言。**

### 2. Mixin 上用 `declared_attr` 的列不能直接比较

`TenantScopedMixin.tenant_id == tenant_id` 会抛
`Cannot compile Column object until its 'name' is assigned`——
`declared_attr` 声明的是「模板」，只有被子类继承时才生成真正的 Column。

修法：传 callable 给 `with_loader_criteria`，延迟到拿到实体类再求值。

## Windows / zh-CN 环境坑（已写进 README）

1. **`alembic.ini` 必须纯 ASCII**——`configparser` 用 GBK 读它，含中文直接崩。
2. **`alembic/env.py` 必须保留 `# -*- coding: utf-8 -*-`**（已就地 `noqa: UP009`
   并注明原因）——Alembic 用系统编码读该文件。
3. **`JSONB` 不能直接当列类型**——SQLite 渲染不了，建表即 `CompileError`。
   必须 `JSON().with_variant(JSONB(), "postgresql")`。
4. **autogenerate 生成 `with_variant` 列会漏 `Text` 导入**——已在
   `script.py.mako` 预置 `from sqlalchemy import Text`。

> 提示：环境坑 1、2 是同一类根因（Alembic 不指定 encoding，依赖系统 locale），
> 以后遇到 Alembic 相关文件加中文注释时先想到这一点。
