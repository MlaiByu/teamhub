机器上共有 2 个 Python，**没有一个是「teamhub 自己装的」**：

| 位置 | 版本 | 说明 |
|---|---|---|
| `D:\python10\python.exe` | 3.10.11 | 系统装，已注册到 `py` 启动器（`py -0` 显示 `-3.10-64`） |

**坑：托管运行时的目录名（3.13.12）与实际版本号（3.13.14）不一致**——
目录按 3.13.12 命名，里面装的是 3.13.14。看路径会误判，以 `sys.version` 为准。
（`pyvenv.cfg` 里 `home` 指向 3.13.12 目录，但 `version = 3.13.14`。）

**PATH 上的 `python` 解析到托管运行时**（3.13.14），不是 `D:\python10`。
所以 README 里 `python -m venv .venv` 这条指令在当前环境能直接跑通，
靠的是 WorkBuddy 把托管运行时放进了 PATH——不是用户自己装过 Python。

teamhub 的 `.venv` 就是由托管运行时创建的：
`include-system-site-packages = false`，与系统包完全隔离。

## 咨询记录：venv 不能凭空创造 Python

用户问「如果没有下载 Python 能不能 venv 一个」。结论：**不能**。

`venv` 是 Python 标准库里的一个模块（`python -m venv`），
它本身不是独立程序，必须先有一个已安装的解释器才能调用。
且 venv 只是「壳」——`pyvenv.cfg` 的 `home` 键指回基础解释器，
标准库仍从基础解释器读取，venv 目录里没有 Python 本体。

要在无 Python 的机器上跑起来，只有三条路：装一个 / 用能自带解释器的工具
（uv、conda 可下载并托管 Python）/ 走 Docker（本项目 Dockerfile 已就绪）。

> 本次为**咨询**，未改任何代码或文件。

### 核心发现 1：默认配置根本起不来（P0 真 bug）

`uvicorn app.main:app` 在**无 `.env`** 时直接崩：

```
sqlalchemy.exc.InvalidRequestError: The asyncio extension requires an async driver
to be used. The loaded 'pysqlite' is not async.
```

根因是 `config.py` 里两个缺陷叠在一起：

1. **默认值本身是坏的**：`database_url` 默认写成 `sqlite+pysqlite:///:memory:`
   （同步驱动）。`create_async_engine` 不接受同步驱动，模块导入即抛。
2. **归一化器漏了这一种写法**：`_normalize_async_driver` 只匹配 `sqlite://` 前缀，
   而 `sqlite+pysqlite://` 不以 `sqlite://` 开头（`+pysqlite` 插在中间），
   所以**原样透传**，没被改写成 aiosqlite。

实测归一化矩阵（修复前 → 修复后）：

| 输入 | 修复前 | 修复后 |
|---|---|---|
| `sqlite:///:memory:` | ✅ 改写 | ✅ 改写 |
| `sqlite+pysqlite:///:memory:` | ❌ **原样透传 → 崩** | ✅ 改写 |
| `postgresql://...` | ✅ 改写 | ✅ 改写 |
| `sqlite+aiosqlite://...` | ✅ 不动 | ✅ 不动 |

**为什么一直没被发现**：`tests/conftest.py` 显式设了 `DATABASE_URL=sqlite+aiosqlite:///:memory:`，
CI 的 `env` 块也设了。所以测试和 CI 全绿，**只有「真去跑 uvicorn」这一条路径是坏的**。
之前记忆里那条「`/health` 实测通过」是通过 `client` fixture 走的 ASGI 直连，
不是真的起 uvicorn——这类「测试绿 ≠ 能启动」的缺口值得警惕。

修复时要注意：**不能用 `str.replace` 做前缀改写**。链路是
`sqlite+pysqlite://x` → 先 replace 成 `sqlite+aiosqlite://x` → 再 replace `sqlite://`
会**再次命中内层的 `sqlite://`**（`aiosqlite://` 里就含 `sqlite://`），
拼出 `sqlite+aiosqlite+aiosqlite://x` 这种畸形 URL。
改用「前缀切片拼接」：`"sqlite+aiosqlite://" + v[len(prefix):]`。
